# Magistrate Wizard — working notes for agents

Legal knowledge management for magistrates: court-anchored docket, judgments, bench notes, curated legal library, sharing, notifications. React 18 + Vite + TypeScript + Tailwind/shadcn + TanStack Query + Zustand; Supabase (Postgres/RLS/Storage/edge functions); Capacitor and Electron shells around the same `dist/`. Node 24, npm 11.

## Where things live

- `src/pages/<feature>/` one folder per feature; a page imports only its own folder. `src/hooks/<feature>/` TanStack Query hooks. `src/lib/` framework-free domain logic (no React imports; ESLint enforces both rules).
- `src/types/database.types.ts` is generated (`npm run supabase:types`) — never hand-edit. Aliases go in `src/types/db-aliases.ts`; import from `@/types`.
- Routes: `src/routes/paths.ts` (never hardcode a path). Roles: `UserRole` in `src/lib/constants.ts`.
- `supabase/migrations/` forward-only SQL; `supabase/functions/` edge functions; `supabase/README.md` for the loop.
- Tests: `scripts/tests/test-*.mjs` (plain Node, discovered by `scripts/test-support/run-all.mjs`); `e2e/` Playwright.
- CSP source of truth: `scripts/content-security-policy.ts`; `vercel.json` is generated by `npm run csp:sync`.
- Docs: `DEVELOPMENT_WORKFLOW.md` (rules), `docs/adr/` (invariants), `docs/environments.md`, `docs/backup-and-recovery.md`, `docs/architecture/`.

## Non-negotiables (details in DEVELOPMENT_WORKFLOW.md)

- Never edit an applied migration; fix forward with a new one. One number per file, reconciled against live history.
- Every schema/RLS change follows the full 13-stage database change workflow; disposable fixtures only, never the real admin profile.
- The security/privacy invariants in `docs/adr/` (owner-only quick codes, owner-or-discoverable judgments, author-only bench notes, three-path docket access, view/edit share distinction, no admin bypass, asymmetric association tables) are not reopened for convenience.
- No `git reset --hard`, `git clean -fd`, force pushes or silent conflict resolution without explicit authorisation. No secrets in the repo; `.env.example` only.
- Do not push unapplied migrations to `main` as if they were live.

## Test and tooling conventions

- `npm test` = every non-live, non-slow script; `npm run test:live` needs `npm run db:start`; `npm run test:slow` adds the brutal variants; `npm run test:e2e` for Playwright. New scripts: `scripts/tests/test-<name>.mjs`, tag `// @live-db` / `// @slow` in the first 20 lines, add an `npm run test:<name>` alias.
- Scripts import the real `src/lib` modules through the `@/` loader (`--import ./scripts/test-support/register.mjs`); `@/lib/supabase` is stubbed. No `--experimental-strip-types` (Node 24 strips types by default).
- `npm run lint` is zero-warning and includes `jsx-a11y`; `npm run typecheck` is `tsc -b`. Husky runs lint-staged on commit and typecheck on push.
- Prettier: semicolons, double quotes, trailing commas, 100 columns, LF. Formatting-only changes go in their own commit — never mix reformatting with logic.
- British spelling in user-facing copy, docs and commit messages (colour, organisation, licence; "judgment" is the legal term).
- Commit messages: `type(scope): what verified state resulted`, one logical milestone per commit; migrations and their spec changes together, frontend separately where practical.
